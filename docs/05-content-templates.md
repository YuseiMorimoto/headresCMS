# 05. 記事テンプレート仕様

記事の型は3種のみ。増やさない。型が増えるとレビューが定型化できず、週6本のペースが維持できなくなる。

> ジャンル確定後、各テンプレートの見出し文言を具体化すること。構造そのものは変更しない。

## comparison — 比較記事

クラスタのピラー記事は原則この型を使う。

```
H1: {対象カテゴリ}のおすすめ{N}選【{年}年】
  リード（結論の先出し。3行以内）
  H2: 結論：目的別のおすすめ
    → 3パターン程度の推奨と理由。ここに offers を配置
  H2: 選び方の基準
    H3: 基準1 / 基準2 / 基準3
  H2: 比較表
    → ComparisonTable コンポーネント
  H2: 各社の詳細
    H3: {サービスA}
    H3: {サービスB}
    …（各 H3 の末尾に offers）
  H2: 実際に使って分かったこと  ← firsthand
  H2: よくある質問
  H2: まとめ
```

要件:
- 比較表は最大6行 × 5列。それ以上は情報過多で読まれない
- 比較表の各行末尾に `/go/` リンクを置く
- 子記事（review型）への内部リンクを各 H3 から必ず1本張る

## review — 単体レビュー記事

```
H1: {サービス名}の評判は？{切り口}を解説
  リード
  H2: 結論：どんな人に向くか
  H2: 基本情報
    → SpecTable コンポーネント（料金・提供元・対応範囲など）
  H2: メリット
  H2: デメリット
  H2: 実際に使って分かったこと  ← firsthand（この型では特に厚く）
  H2: 他サービスとの違い
    → 親のピラー記事（comparison）へ内部リンク
  H2: よくある質問
  H2: まとめ
```

要件:
- offers は「結論」直後と「まとめ」直前の2箇所のみ。本文中に散らさない
- デメリットを必ず書く。メリットのみの記事は作らない

## guide — 解説記事

収益直結ではなく、クラスタへの流入を作る記事。

```
H1: {テーマ}とは？{読者の疑問}を解説
  リード
  H2: 結論・要点（箇条書き3〜5点）
  H2: 詳細解説
    H3: …
  H2: 具体例・実践方法  ← firsthand を含める
  H2: 注意点
  H2: 関連情報
    → 同一クラスタの comparison / review へ内部リンク
  H2: まとめ
```

要件:
- offers は0〜1件。原則置かない
- 内部リンクで収益記事へ送るのが役割

## 共通ルール

- H1 は1ページに1つ。`title` と一致させる
- 見出し階層を飛ばさない（H2 の次に H4 を置かない）
- H2 は最大8個。超える場合は記事を分割する
- 1記事 3,000〜6,000字を目安（型を問わず）
- 段落は3文以内。1文40字前後
- 数値・日付を書いた箇所には取得日を併記する
- 断定表現は一次ソースで確認できたものに限る

## 必須コンポーネント

| コンポーネント | 用途 | 要件 |
|---|---|---|
| `<PrNotice />` | PR表記 | 全記事の本文冒頭。`offers` が空でも表示 |
| `<OfferButton />` | 案件リンク | `/go/{slug}`、`rel="sponsored nofollow noopener"` |
| `<ComparisonTable />` | 比較表 | モバイルで横スクロール。最大6行×5列 |
| `<SpecTable />` | 基本情報 | 定義リストとしてマークアップ |
| `<Firsthand />` | 一次情報 | 見出し付きで視覚的に区別。空なら**ビルドエラー** |
| `<Faq />` | よくある質問 | 見出しと本文のペア。JSON-LD の FAQPage は出力しない |
| `<Toc />` | 目次 | H2/H3 から自動生成。JSは使わない |
| `<RelatedPosts />` | 関連記事 | 4件。同一クラスタ優先 |

## 表現の禁止事項

CI で NGワード検査を行う（`scripts/lint-content.ts`）。

- 医薬品的な効能効果の断定（薬機法）
- 「必ず」「100%」「日本一」など根拠のない最上級・断定（景表法）
- 「今だけ」「先着◯名」など、実際に期間限定でない場合の煽り表現
- 他社を貶める比較表現

検出時はビルドを警告付きで通し、PR にコメントする（ブロックはしない。誤検知が多いため）。
